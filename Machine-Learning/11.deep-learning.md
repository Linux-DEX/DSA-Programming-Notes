# Deep Learning

Deep learning is machine learning with models built from many layers of simple units. The layer count is not the point. The point is that the features are **learned** rather than built by hand. Classical learning starts from a table someone engineered. Deep learning starts from pixels, characters, wave forms, or tokens, and shapes its own intermediate representation on the way to the target.

You still need everything in the earlier notes: a split, a loss, held-out evaluation, and a metric that matches the decision. What changes is scale — of the model, of the data, and of the engineering around training.

## The multilayer perceptron

A stack of affine transforms and element-wise non-linearities:

```text
h₁ = act(W₁ x + b₁)
h₂ = act(W₂ h₁ + b₂)
ŷ  = out(W₃ h₂ + b₃)
```

The non-linearity is what earns the layers. Without it, `W₃ W₂ W₁` collapses into one matrix. With it, the network can represent curved boundaries and interactions between features. A fun result from classical theory says even one wide hidden layer can approximate any continuous function. That result does not say one layer is a good idea — depth lets the model reuse parts of the computation and trains more cheaply per unit of expressiveness.

### Activations

| Activation | Formula | Where it is used |
| --- | --- | --- |
| Sigmoid | `1 / (1 + e^(−z))` | Binary probability output; rare in hidden layers now |
| Tanh | `tanh(z)` | Squashes to (−1, 1); classic RNN cells |
| ReLU | `max(0, z)` | Cheap default for hidden layers; can “die” if a unit’s input stays negative |
| Leaky ReLU / GELU | variants that leak or smooth zero | Fixes for dead units; GELU is common in transformers |
| Softmax | normalized exponentials over classes | Multiclass output layer |

Hidden layers use the smooth fast ones. The output layer is chosen by the task: sigmoid for one probability, softmax for a class, linear for regression.

### Backpropagation

Backprop is the chain rule, bookkept so each intermediate result is reused. One training step:

```text
forward pass → loss → backward pass (gradients) → optimizer update
```

Nothing new mathematically. The engineering is in doing it across millions of weights, in parallel, many times per second.

### Why deep nets are hard to train

- **Vanishing gradients.** Sigmoid and tanh squash; their derivatives get tiny for large inputs. Early layers receive a product of many tiny numbers and stop learning. Fixes: ReLU-style activations, residual connections, normalization, careful initialization.
- **Exploding gradients.** The same product can blow up. Fixes: gradient clipping, initialization.
- **Internal covariate shift, informally.** As earlier layers move, later layers see a distribution that keeps moving. Fixes: **batch normalization** (normalize a layer’s outputs over the batch, with learned scale and shift) and **layer normalization** (normalize per example; the standard in transformers).

Initialization matters: weights too large saturate, too small silence the signal. Variance-preserving schemes (Xavier, He) are the defaults in every framework and you rarely roll your own.

## Training on accelerators

| Idea | What it does |
| --- | --- |
| Mini-batch SGD | The unit of work is a batch sized to fill the GPU |
| Adam / AdamW | Per-coordinate adaptive steps; the default optimizer. AdamW fixes weight decay so it is regularization, not adaptive scaling |
| Learning-rate schedule | Warm up, then decay (step, cosine). The single most consequential knob |
| Mixed precision | Half-precision math where it is safe; doubles speed |
| Gradient accumulation | Effective batch bigger than memory allows |

Practical order of operations when a network misbehaves: check the loss scale and the learning rate first, then overfit a tiny subset (a small model should drive training loss near zero; if it cannot, there is a bug), then add capacity or data. Reading individual weights is rarely the diagnosis.

## Hyperparameters that matter most, roughly in order

1. Learning rate and its schedule.
2. Model capacity for the amount of data.
3. Batch size (interacts with learning rate).
4. Regularization: weight decay, dropout, augmentation strength.
5. Depth/width of the specific architecture.

## Convolutional networks

Images exploit a prior: a cat is a cat in the top-left as well as the bottom-right, and edges matter everywhere. A fully connected layer would relearn every position separately. Convolution shares the weights.

- A **convolution layer** slides a small filter across the image. The filter is a feature detector; applying it everywhere produces a feature map.
- **Pooling** (max or average) shrinks each map so later layers see a wider view. A unit deep in the network has a **receptive field** covering a large patch of the original image.
- Stacking conv → activation → pooling builds the hierarchy: edges → textures → parts → objects.

```text
image → [conv → relu → pool] → [conv → relu → pool] → flatten → dense → softmax
```

Conventions learned from practice:

- Small filters (3×3), stacked deep, beat wide shallow ones.
- **Residual connections** (`output = F(x) + x`) let very deep networks train by giving each block an easy identity path. Grinding depth without them used to degrade before it improved.
- **Data augmentation** (flips, crops, color jitter) is the image world’s regularization. It is part of the definition of the dataset, and it must reflect what variation the deployment will actually see.

Where CNNs lose to alternatives: they assume local structure. For most vision tasks they still work well, though vision transformers (which chop the image into patches and let attention find relationships anywhere) have taken the top of many leaderboards.

## Recurrent networks and why they lost their job

A **recurrent network** processes a sequence one step at a time, carrying a hidden state:

```text
h_t = f(W_x x_t + W_h h_{t−1})
```

The same weights apply at every step, so the network handles any length, and it trains by backpropagation **through time**. That is where the vanishing gradient returns: the gradient to step `t−10` is a product of ten factors through the recurrence.

**LSTM** and **GRU** cells add gates that learn how much of the old state to keep, erase, and write. This made long-range dependencies trainable and powered speech and translation for years.

The structural cost is that time is sequential. The network cannot look directly at step 3 while processing step 30 — it has to carry everything through the hidden state. And training cannot parallelize across time steps the way convolution parallelizes across patches.

## Attention and the transformer

Attention replaces “compress everything into a running state” with “look directly at exactly what you need.” For a query vector `q`, compare it with key vectors `kⱼ` from every position, normalize the similarities into weights, and take a weighted sum of the value vectors `vⱼ`:

```text
attention(q, K, V) = Σⱼ softmax(q · kⱼ) vⱼ
```

Every position can attend to every other position in one layer. The computation parallelizes across the whole sequence, which is what GPUs reward, and the path from step 3 to step 30 is length one, not a chain of 27 squashed factors.

A **transformer** stacks these blocks, each of the form:

```text
x → layer-norm → multi-head self-attention → add residual
  → layer-norm → small MLP → add residual
```

- **Multi-head** runs several attention patterns side by side, so one head can track syntax while another tracks coreference.
- **Positional encodings** inject order, because attention by itself is a bag of tokens.
- Residuals and layer norm make deep stacks trainable.

Two pretraining styles split the field:

| Style | Trains by | Reads like | Typical products |
| --- | --- | --- | --- |
| Masked (BERT-style) | Predict hidden tokens from both sides | A representation learner | Encoders for classification, search, NER |
| Autoregressive (GPT-style) | Predict the next token from the past | A generator | Language models, which grew into general instruction-following models |

See [12.nlp-and-llms.md](./12.nlp-and-llms.md) for what happens after this pretraining.

## Generative models

Everything above builds a function from input to output (or to a probability over outputs). **Generative models** learn the distribution of the data itself, so they can draw new samples from it: new images, molecules, audio, text. The family is best understood by how each member says “make me a plausible example.”

### Autoencoders and variational autoencoders

A plain **autoencoder** compresses the input through a bottleneck and reconstructs it; the code is trained to keep whatever reconstruction needs. It reconstructs the data it saw; it is not built to invent new data.

The **variational autoencoder (VAE)** turns the code into a **distribution**. The encoder produces a mean and a variance per dimension, sampling injects noise so nearby codes interpolate, and the loss pulls each code’s distribution toward a standard normal (`KL` regularization, from [3.math-for-ml.md](./3.math-for-ml.md)) while punishing bad reconstruction. The result is a smooth latent space: move between two codes and samples blend; sample the prior and a new example appears. The trade-off: VAE samples are famously a little blurry, because the averaged likelihood objective rewards “safe” images.

### Generative adversarial networks

A **GAN** makes generation a two-player game:

```text
generator:  noise → candidate image        tries to fool the discriminator
discriminator: real/fake classifier        tries to tell truth from forgery
```

Each trains against the other. It produces sharp samples when stable. The discipline notes from practice: the game is unstable (the two losses do not have to move toward a shared optimum), **mode collapse** is the classic failure (a generator that makes a few crowd-pleasing outputs and nothing else), and no likelihood objective means hard-to-measure training progress — monitoring is heuristic by nature.

### Diffusion

**Diffusion models** broke the “diffusion vs GAN” tie that ran through image generation for two years:

1. **Forward process:** corrupt a training image by adding a little noise, many times, until it is pure noise. This schedule requires no learning.
2. **Learn to reverse it:** train a network (usually a U-Net style conv stack, today often with attention blocks) to predict the noise that was added at each step.
3. **Generate:** start from pure noise and subtract learned noise a step at a time, guided by conditioning — a text embedding, a class label — so the walk lands inside the region the condition describes.

Why it won: the training objective is a simple denoising regression (stable where GANs are not), the model class reuses proven architectures, and the step-by-step procedure trades sampling time for fidelity at a knob the practitioner controls. The engineering pain moved to the other side: sampling is many forward passes, so latency comes from the number of steps, and distillation or fast schedulers exist largely to cut that cost.

### Text-to-image and conditioning

Modern image systems are diffusion (or AR-token) models with a **cross-attention** path that lets a text encoder (a contrastively trained image–text pairer, CLIP being the archetype) steer the denoising at every step. The general lesson is portable: the *generator* is one component; the *conditioning encoder* decides what the generation is about, and most prompt-dependent quality problems live in that encoder, not in the denoiser.

## Transfer learning

Training from scratch is the exception. The normal path:

```text
pretrained model (from public training, on vast data)
→ fine-tune on your labeled data (small relative to pretraining)
→ evaluate on a held-out set from your distribution
```

Fine-tuning updates all weights (full fine-tune) or a small part of them. **Parameter-efficient** methods (adapters, LoRA) train a few small matrices alongside frozen weights and get most of the benefit on a fraction of the compute. **Feature extraction** — freeze everything, train only a classifier head — is the cheapest and often enough when your data is tiny.

The same split logic as always applies: fine-tune on training rows, tune the fine-tune on validation, report once on test.

## Regularization recap, deep-learning edition

- **Dropout**: randomly zero units during training. As a side effect it approximates an ensemble. Turn it off (or scale it) at inference.
- **Weight decay (L2)**: small weights, smoother functions. In AdamW it is decoupled from the adaptive step.
- **Early stopping**: checkpoints and validation loss. Often the strongest regularizer in the pile.
- **Augmentation**: label-preserving distortions. The best augmentation encodes what invariances you want the model to have.
- **Pretraining** itself: representations learned on large data start closer to the solution, which is a form of regularization for the fine-tune.

## When to reach for deep learning

Reach for it when the raw input is itself the problem — pixels, audio, long text, code, sensor traces where the informative intermediate features are unknown — and there is enough data (or a pretrained model close to the domain).

Stay with trees and linear models when the input is a modest table of engineered columns. On most tabular problems a gradient-boosted tree still matches or beats a deep net at a fraction of the cost, and it explains itself better. Matching the architecture to the input’s structure (convolution for grids, recurrence or attention for sequences) matters more than raw size.

## Checklist before trusting a trained network

- The model overfits a small subset (sanity check on the training machinery).
- Validation loss, not training loss, drives every decision in the training log.
- Augmentation and preprocessing match what deployment will feed.
- Learning curves exist; capacity was not chosen by vibes.
- The checkpoint being served is the one with the best validation metric, and the test set answered one question, once.
